# PaperDNA evaluation

This document describes **what PaperDNA was evaluated on, how, and with
which honest limits**. Every number below is produced by a committed
report in [`docs/evaluation/reports/`](reports/) from actual predictions
against hand-labeled data, and can be regenerated byte-for-byte with the
commands shown. Nothing here is a claim of scientific model quality.

## TL;DR

| What | System | Split | Headline metric |
|---|---|---|---|
| Retrieval | lexical fallback (the app's real offline ranker) | test (13 queries) | P@1 = 1.00, R@5 = 1.00 |
| Relation classification | lexical-overlap floor baseline | test (16 pairs) | macro-F1 = 0.656 |
| Relation classification | scripted fixture replay | all (24 pairs) | accuracy = 1.00 (**circular — plumbing only**) |
| Condition comparison | deterministic rule baseline | all (6 pairs) | 6/6 statuses correct |
| Evidence traceability | attribution module (audit) | 38 evidence sides | 0 violations |
| Relation classification | real NLI cross-encoder | — | **not run in this environment** (see below) |
| Retrieval | real sentence-transformers embedder | — | **not run in this environment** (see below) |

## Datasets

All evaluation data is **synthetic, hand-authored, and committed** in
[`tests/fixtures/`](../../tests/fixtures/). No external dataset was
downloaded; no real scientific corpus is sampled; every `_comment` field
in the fixtures states this on the file's face.

### Retrieval benchmark — `retrieval_eval.json`

- **13 synthetic papers** (the 3 original fixture papers plus 10
  benchmark papers in the same style), each with title and abstract.
- **19 queries**, each labeled with its full set of relevant paper ids:
  **6 dev** (iteration) and **13 test** (reporting). Splits are
  disjoint; every paper is labeled relevant for at least one query;
  loaders reject any query referencing an unknown paper.
- Labels are *topical relevance judged from title/abstract text by a
  single annotator*. Four dev queries are marked `anchor`: their
  distinctive tokens appear in exactly one paper, so any token-overlap
  ranker must place that paper first (regression guard).

### Labeled claim pairs — `nli_pairs.json`

- **24 pairs** (8 dev / 16 test), each with premise/hypothesis
  sentences, a gold label (`entailment` / `contradiction` / `neutral`),
  and an `expected_uncertain` flag following the documented rule
  (`uncertain = max score < 0.6 or hedges present`).
- Both splits contain all three labels.
- Coverage includes: verbatim support, paraphrase, direction reversal,
  numeric mismatch, negation, hedged premises/hypotheses,
  condition-dependent conflicts, and same-topic-different-finding
  cases.
- Each pair also carries `scripted_scores`: the deterministic fake
  classifier's scripted outputs, authored **from the gold labels**.
  These exist to validate pipeline plumbing and are circular by
  construction — the runner flags them `circular: true`.

### Condition pairs — `conditions_eval.json`

6 hand-labeled pairs with expected per-category statuses (dataset,
population, model, metric, setting, design), including an empty-premise
edge case.

### Evidence audit input

The audit runs on attributions **actually generated** by the evidence
module over the demo corpus: extracted claims self-attributed (verified
path), claims attributed without records (unverified path), and
classification-only attributions (offsets inferred by search).

## Systems measured

1. **Lexical fallback** (`rank_lexically`) — the app's real offline
   ranking: fraction of query content tokens present in title+abstract.
   Token overlap, **not semantic similarity**; the report labels
   `ranking_kind: "lexical"`.
2. **Lexical-overlap NLI baseline** — a deterministic Jaccard-overlap +
   negation-parity heuristic whose predictions are **independent of the
   gold labels**, so its metrics are genuine measurements and a floor a
   real NLI model must beat.
3. **Scripted fixture replay** — circular plumbing validation, reported
   separately and never as model performance.
4. **Real models** (sentence-transformers embedder, CrossEncoder NLI) —
   optional extras, never downloaded implicitly. **Not installed and
   not run in the environment where these reports were generated.**
   To run them explicitly:

   ```bash
   pip install -e ".[embed,nli]"   # downloads the models (~several hundred MB)
   python -m paperdna.eval retrieval --semantic --split test
   python -m paperdna.eval nli --classifier model --split test
   ```

## Metric definitions

- **P@k** — fraction of the top-k retrieved that are relevant.
  Fewer than k retrieved divides by k (missing results count against
  the metric); empty relevance sets would score 0.0 (the loader
  rejects them).
- **R@k** — fraction of all relevant papers appearing in the top-k.
- **macro-F1** — unweighted mean of per-class F1 over the three
  relationships; classes with no predictions or no gold labels score
  0.0 rather than dividing by zero.
- **Uncertain** — `max score < 0.6` or a hedge is present on either
  claim; reported as `uncertain_rate` next to every classification
  report.

## Results

### Retrieval (lexical fallback)

Aggregate over the **test** split (13 queries, 13 papers; report:
[`retrieval_test.json`](reports/retrieval_test.json)):

| Metric | @1 | @3 | @5 |
|---|---|---|---|
| Precision@k | 1.000 | 0.333 | 0.215 |
| Recall@k | 0.962 | 0.962 | 1.000 |

Dev split (6 queries; [`retrieval_dev.json`](reports/retrieval_dev.json)):
P@1 = 1.000, R@1 = 1.000, R@3 = R@5 = 1.000.

**Failure case (honest):** the one multi-relevant query — *"dense
retrievers for scientific literature domain adaptation"* (relevant:
`demo:p002`, `demo:p006`) — retrieves only one of the two at k=1
(R@1 = 0.5): token overlap cannot tell that a paper about *distribution
shift* is also relevant to a *domain adaptation* query. This is the
lexical baseline's core limitation and exactly what a semantic model
would be measured against.

### Relation classification (overlap floor baseline, test split)

Report: [`nli_overlap_test.json`](reports/nli_overlap_test.json);
n = 16; macro-F1 = **0.656**; accuracy = 0.625; uncertain rate = 0.312.

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| entailment | 0.60 | 0.43 | 0.50 | 7 |
| contradiction | 1.00 | 0.67 | 0.80 | 3 |
| neutral | 0.56 | 0.83 | 0.67 | 6 |

Dev split: macro-F1 = 0.500 (n = 8).

**Failure cases (honest, all six misses on the test split):**
paraphrases with shifted vocabulary are missed (`entailment → neutral`)
for *"gradient stabilization / stabilizing gradients"*, *"attention is
beneficial for summarization"*, specific→general entailment, and
cross-paper paraphrase; a negation-free temporal contrast
(*disappeared vs persisted*) is missed (`contradiction → entailment`);
and a condition-dependent conflict (*large vs small datasets*) is
over-read as entailment. These are the expected blind spots of pure
token overlap — and precisely the cases NLI models exist for.

### Scripted conformance (circular, plumbing only)

Report: [`nli_scripted_conformance.json`](reports/nli_scripted_conformance.json);
n = 24, accuracy = 1.000, macro-F1 = 1.000, uncertainty flags agree on
all 24 pairs. **This is not a quality metric**: the scripted scores were
authored from the gold labels. It proves `classify_pair` plumbing,
thresholding, and uncertainty propagation behave exactly as documented;
a regression would show as < 1.0.

### Condition comparison (rule baseline)

Report: [`conditions_correctness.json`](reports/conditions_correctness.json);
**6/6 pairs, every category status correct**, including the
empty-premise edge case. This is a correctness check of a deterministic
rule system, not a quality score.

### Evidence traceability audit

Report: [`evidence_audit.json`](reports/evidence_audit.json);
19 attributions / **38 evidence sides**, **0 violations**:

| Verification state | Sides | Meaning |
|---|---|---|
| `verified` | 16 | `abstract[start:end] == sentence` checked exactly |
| `verified_by_search` | 14 | offsets inferred by unique occurrence (classification-only path) |
| `unverified` | 8 | no record available at attribution time; reason stated |

Checked invariants: verbatim sentence text, exact offsets for verified
states, stated reasons for every gap, `unknown` (never guessed) claim-id
component when offsets are unavailable, and stable claim ids. Negative
tests prove the audit *detects* fabricated offsets and forged claim ids.

## What is not verified

- **Real-model tiers**: semantic retrieval P@k/R@k and genuine NLI
  macro-F1 from a trained cross-encoder were **not measured in this
  environment** (models not installed; downloads are always explicit).
  The commands above reproduce them when the optional extras exist.
- **Real scientific corpora**: the benchmarks are tiny, synthetic, and
  single-annotator. They measure regression safety and honest pipeline
  behavior — not generalization to real literature.
- **Scientific truth**: NLI labels describe *textual* relationships.
  A support label never means "the claims are scientifically true".
- **Calibration**: all scores (NLI softmax, cosine similarity) are
  uncalibrated; no probability claim is made anywhere in the UI or API.

## Limitations and failure modes

1. **Small-n variance**: with 13 queries / 16 pairs, one flipped item
   moves a metric by 4–6 points. Per-query/per-pair rows are committed
   so every aggregate is auditable.
2. **Single annotator**: labels are subjective; no inter-annotator
   agreement was measured (the fixture labels are documented as
   sanity-checks on their face).
3. **Lexical baseline blindness**: paraphrases, negation nuance, and
   condition-dependent findings are its documented failure modes (see
   failure cases above).
4. **Scripted circularity**: structural separation in the runner
   (`circular: true` flag) exists specifically so these numbers can
   never be mistaken for model metrics.
5. **Fixture drift**: benchmark loaders fail loudly on unknown splits,
   duplicate names, unresolvable references, and unlabeled papers, so a
   broken fixture cannot silently skew metrics.

## Reproducing every number

```bash
pip install -e ".[dev,api]"          # offline tier; no models, no downloads
python -m paperdna.eval all --out report.json    # full offline tier
python -m paperdna.eval retrieval --split test   # or dev / all
python -m paperdna.eval nli --split test --classifier overlap
python -m paperdna.eval conditions
python -m paperdna.eval evidence
```

Output is deterministic (sorted keys, no timestamps): two runs on the
same checkout produce byte-identical JSON — asserted by
`tests/evaluation/test_runner_cli.py::test_all_is_byte_deterministic`.
The pytest suite (`pytest tests/evaluation`) re-derives the metric math
on synthetic inputs with known expected values, validates the fixtures'
internal consistency, and runs the end-to-end integration invariants.
